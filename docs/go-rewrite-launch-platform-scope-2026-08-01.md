# Go 后端首发平台范围

日期：2026-08-01

状态：已确认，作为阶段 4 和最终阶段 8 候选的外部平台验收边界。

## 结论

Go 后端首发必须真实支持的外部平台只有：

1. 网易云音乐（Netease）
2. 哔哩哔哩（Bilibili）

本地曲库（Local library）不是外部平台，但属于首发核心能力，和上述两个真实平台一样是候选发布硬门槛。

YouTube、Navidrome、Squidify 以及管理员动态添加的 Subsonic 数据源属于条件支持：只有部署管理员明确配置并启用时，才需要使用对应凭据验收；缺少这些私有凭据不会阻塞首发。

## 首发硬门槛

### 网易云音乐

使用实际部署的 NeteaseCloudMusicApi 和获授权的运行时 Cookie，至少完成一次：

- 搜索返回真实歌曲；
- 选择歌曲后取得权威名称、艺术家、时长和封面；
- 入队并开始播放；
- 通过 Go 媒体代理取得实际音频；
- Range 请求、拖动进度和继续播放正常；
- 不再只以免登录试听片段作为完整验收结果。

### 哔哩哔哩

使用有效的 `BILIBILI_SESSDATA`，至少完成一次：

- WBI 搜索返回真实视频；
- 读取一个当前实现支持的用户收藏夹或播放列表路径；
- 选择视频后取得权威标题、作者、时长和封面；
- 入队并通过 Go 媒体代理播放实际音频；
- Range 请求、拖动进度和继续播放正常。

### 本地曲库

使用隔离测试目录，至少完成一次：

- 上传受支持的音频文件；
- FFmpeg 转码完成，状态和时长正确；
- 搜索、入队、播放和 Range 请求正常；
- 删除后数据库记录及受管理媒体文件均被清理。

## 条件支持平台

### YouTube

只有同时启用 `YOUTUBE_ENABLED`、配置有效 `YOUTUBE_API_KEY`，且运行环境中的 `yt-dlp` 可用时才承诺支持。启用后应验收搜索、权威元信息、入队、实际音频和 Range；未配置时平台不应出现在可用平台列表中。

### Navidrome、Squidify 和动态 Subsonic

只有管理员配置并启用具体数据源时才承诺支持。启用后应使用该部署自己的测试账号验收登录、访问控制、搜索、元信息、入队、媒体代理和 Range。没有用户私有服务或凭据时，不要求为首发临时搭建外部服务。

## 验收位置和证据

- 不要求远端 CI 执行真实平台验收；本机通过 Docker 连接真实上游即可。
- 如果真实上游只允许 VPS 网络访问，可在不触碰生产数据库的前提下，于候选镜像的隔离实例执行。
- 凭据、Cookie、媒体响应和账号信息不得写入 Git。
- 最终只固化脱敏文本或 JSON：候选提交 SHA、镜像 digest、时间、平台、执行路径、HTTP/Range 结果和通过/失败结论。
- fixture 和 mock 测试继续用于日常回归，但不能代替上述首发平台的真实上游验收。

## 与阶段状态的关系

- 阶段 4：代码、fixture 和错误处理可以先收口；网易云与哔哩哔哩的真实上游硬门槛必须明确存在且可执行。
- 最终阶段 8 候选：网易云、哔哩哔哩和本地曲库必须在同一个最终候选提交或镜像上通过。
- 条件支持平台只在该次部署明确启用时加入最终候选门禁。
