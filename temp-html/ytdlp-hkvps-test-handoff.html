下载、中断、续传

  1. 在 hkvps 上以普通用户、独立 Bash 会话运行。先检查磁盘余量及 yt-dlp、ffprobe、ffmpeg 和受支持的 JS 运行时；记录版本。缺依赖时按官方 EJS 指南配置隔离环境，不升级宿主机全局依赖。
  2. 在独立目录列出格式，挑一个音频专用格式。优先选普通 HTTPS 格式以便检查字节续传；如果只有分片格式，记录协议与分片进度。不要预设某个格式 ID 一定可用。
umask 077
work=$(mktemp -d -t musicparty-ytdlp.XXXXXXXX) || exit 1
cd "$work" || exit 1
url='https://www.youtube.com/watch?v=0Ojarj6nTM4'
yt-dlp --version
yt-dlp --ignore-config --no-cache-dir --no-playlist \
  --socket-timeout 15 --retries 1 -F "$url"
  1. 把 format 设为上一步实际选中的格式 ID。两次都使用同一个目录、输出模板、格式、工具版本及运行时参数；不加转码或覆盖选项。先限速下载，在 .part 已有非零字节后按 Ctrl+C。若文件已经下载完成，这次不算中断测试；用新目录重做，不覆盖已有文件。
format='填入已确认的音频格式 ID'
download_audio() {
  timeout --signal=INT --kill-after=10s 5m yt-dlp \
    --ignore-config --no-cache-dir --no-playlist --continue --part \
    --socket-timeout 15 --retries 1 --fragment-retries 1 \
    --abort-on-unavailable-fragments --max-filesize 64M \
    -f "$format" -o '%(id)s.%(ext)s' "$@" "$url"
}
download_audio --limit-rate 256K   # 看到 .part 增长后按 Ctrl+C
ls -la                             # 记录 .part 大小，分片格式也保留状态文件
download_audio                     # 保留同目录、同格式、同输出模板

示例假设使用 GNU timeout，如临时环境未提供就用等价的独立超时控制。单视频、单任务；文件大小参数不当作磁盘硬配额，留意实际写入量。若卡在格式提取、403、429、登录验证、PO Token 或 JS challenge，记录发生阶段和脱敏后的错误，不反复重试。

  1. 续传要有证据：中断时的字节数或分片编号，以及第二次日志的非零续传偏移或分片起点。若日志显示从头重下，即使最后成功，也只算下载通过，不算续传通过。yt-dlp 的默认 --continue 和 --part 并不保证每种上游格式都能恢复。
  2. 对最终文件用 ffprobe 检查音频流、编码、容器、时长和大小；用 ffmpeg -v error -xerror -i "$file" -map 0:a:0 -f null - 整段解码。记下 SHA-256。最终文件必须稳定且可解码，不能把 .part 当成成品。

HTTP Range 验收

临时服务只暴露已验收的那一个文件，不提供目录列表或诊断日志。可用 Go http.ServeContent。显式设置匹配文件的 MIME，例如 M4A 用 audio/mp4，WebM 音频用 audio/webm。在 VPS 本机测试，或通过 ssh -N -L 127.0.0.1:18088:127.0.0.1:18088 hkvps 到本机测试。端口有冲突就换空闲端口，不停止其他服务。

endpoint='http://127.0.0.1:18088/audio'
curl -fsS -D full.headers  -o full.body  "$endpoint"
curl -fsS -D range.headers -o range.body -H 'Range: bytes=1024-2047' "$endpoint"
curl -sS  -D invalid.headers -o /dev/null -H 'Range: bytes=999999999-' "$endpoint"
  • 完整请求返回 200，下载文件的 SHA-256 与原件一致。非零偏移请求返回 206，Content-Range 为 bytes 1024-2047/总字节数，正文大小为 1024 字节，并与源文件对应字节一致。
  • 越界请求返回 416，Content-Range 为 bytes */总字节数。浏览器验收时，用原生音频控件播放并拖到后半段，确认进度继续走、声音恢复；没有实听就注明只验证了 HTTP 和解码。
  • 两种续传分开判定：yt-dlp 恢复的是 VPS 上游下载，Range 恢复的是客户端对已完成文件的读取。任何一项通过都不能替另一项。

交付与下一步

报告三项独立结论：hkvps 下载是否成功、是否实际从非零位置续传、完整性与 Range 是否通过。附格式 ID／协议、工具版本、首次中断字节数／分片编号、恢复位置、最终时长与大小、HTTP 状态、是否实听。单样本只能证实该视频在该次运行中可用，不能证明长期稳定。

结束后停掉测试进程和转发，仅清理明确属于本次实验的临时目录与一次性容器。实验通过也先汇报，不自动接入。接入时再单独讨论下载任务去重、磁盘限额、缓存过期、完成文件原子发布和失败回退；第一版仍只播放完整文件。
